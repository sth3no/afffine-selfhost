# Phase 12.5: YouTube cookie sync — follow-up

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the gap between "the extension says it synced" and "the server actually has fresh, working cookies." Phase 12 shipped the upload pipe; this phase adds the feedback loop — server reports cookie freshness, the extension surfaces staleness in its popup + toolbar badge, and an opt-in extended-scope mode covers the long tail of restricted videos.

**Why now:** Phase 12 is in production. Two real failure modes have surfaced:
1. The extension's "Last sync: ok 5m ago" can lie — if the *ingest container restarted* and the extension hasn't seen a YT cookie change since, the tmpfs file is gone and captures fail with no UI signal.
2. A subset of YouTube content (members-only, age-gated, music with regional rights holds) still trips `Sign in to confirm you're not a bot` because the auth lives on `accounts.google.com`, not `*.youtube.com`. Phase 12 deliberately scoped to YT only; this phase makes the extra scope an opt-in.

**Architecture:** Server gains `GET /youtube/cookies/status` returning `{exists, age_seconds, mtime, byte_count}` — read-only, token-authenticated, never returns cookie content. The extension's existing daily alarm now also fetches `/status` and computes a staleness verdict (`fresh | stale | missing`) which renders in the popup and as a `chrome.action.setBadgeText` red `!` when stale. Extended scope is a single checkbox in options that flips a `hostPermissions` request via `chrome.permissions.request` — the broader cookie collection runs only when the user has granted it.

**Tech Stack:** No new server-side deps (FastAPI + existing `youtube_cookies.py` helpers). Extension-side: existing MV3 surface plus `chrome.permissions` (already available in MV3) and `chrome.action.setBadgeText` (existing).

**Post-phase-12 deviations from the original plan, captured here so the next reader doesn't get whiplash:**
- `os.replace` is used in `write_cookies_atomic` instead of `os.rename` (cross-platform; Windows tolerance).
- `chmod 600` is wrapped in `try/except OSError` — Windows dev filesystems don't honor it, and we don't want the upload to fail in dev.
- The daily-sync alarm is named `yt-cookie-daily-sync`, debounce alarm is `yt-cookie-debounce-sync` (namespaced to avoid collision if more alarms appear).
- The endpoint validator rejects empty bodies via the "no cookie rows" path, not a separate length check — keep this when adding `/status`.

```python
from datetime import datetime, timezone


def cookie_file_status(path: str | Path) -> dict:
    """Return JSON-serializable freshness metadata. Never returns cookie content.

    Used by the read-only GET /youtube/cookies/status endpoint so the
    extension popup can render server-side staleness (the browser-side
    `lastSync` lies if the ingest container restarted and dropped tmpfs).
    """
    p = Path(path)
    try:
        st = p.stat()
    except (FileNotFoundError, OSError):
        return {"exists": False, "age_seconds": None, "mtime": None, "byte_count": 0}

    if not p.is_file() or st.st_size == 0:
        return {"exists": False, "age_seconds": None, "mtime": None, "byte_count": 0}

    mtime_dt = datetime.fromtimestamp(st.st_mtime, tz=timezone.utc)
    age_seconds = max(0, int(datetime.now(tz=timezone.utc).timestamp() - st.st_mtime))
    # ISO-8601 with Z suffix — matches the rest of the API.
    mtime_iso = mtime_dt.strftime("%Y-%m-%dT%H:%M:%SZ")
    return {
        "exists": True,
        "age_seconds": age_seconds,
        "mtime": mtime_iso,
        "byte_count": st.st_size,
    }
```

## Task 3: Extension fetches server status, computes staleness verdict

**Files:**
- Modify: `browser-extension/background.js`

**Staleness rules (these are the only thresholds — change in one place):**
- `fresh`: server reports `exists=true` AND `age_seconds < 86_400` (24h).
- `stale`: server reports `exists=true` AND `age_seconds >= 86_400`.
- `missing`: server reports `exists=false` (tmpfs lost, never uploaded, or wrong path).
- `unknown`: server unreachable or 401 — treat as transient, don't badge.

- [ ] **Step 2: Add a `fetchServerStatus` function**

Add below `cookiesToNetscape`:

```js
/**
 * GET /youtube/cookies/status — returns the server's view of freshness.
 * Never returns cookie content; only `exists`, `age_seconds`, `mtime`, `byte_count`.
 *
 * Returns null on any auth/network failure — caller treats as "unknown",
 * doesn't change badge state.
 */
async function fetchServerStatus(ingestUrl, ingestToken) {
  if (!ingestUrl || !ingestToken) return null;
  const endpoint = `${ingestUrl.replace(/\/$/, '')}/youtube/cookies/status`;
  try {
    const resp = await fetch(endpoint, {
      method: 'GET',
      headers: { 'Authorization': `Bearer ${ingestToken}` },
    });
    if (!resp.ok) return null;
    return await resp.json();
  } catch {
    return null;
  }
}

/**
 * Map a server-status payload to a verdict the popup + badge consume.
 * Returns one of: 'fresh' | 'stale' | 'missing' | 'unknown'.
 */
function verdictFromStatus(status) {
  if (!status) return 'unknown';
  if (!status.exists) return 'missing';
  if ((status.age_seconds ?? 0) >= STALE_AFTER_SECONDS) return 'stale';
  return 'fresh';
}
```

```js
    $status.className = 'status';

  }

    $sv.hidden = true;
    return;
  }
  $sv.hidden = false;

  } else if (result.verdict === 'missing') {
    $sv.className = 'status server err';
    $sv.textContent = `Server: cookies missing. Likely an ingest restart — click Sync now.`;
  }
}
```

```js
async function collectYouTubeCookies() {
  const { extendedScope } = await chrome.storage.local.get('extendedScope');
  const requests = [
    chrome.cookies.getAll({ domain: 'youtube.com' }),
    chrome.cookies.getAll({ domain: '.youtube.com' }),
  ];
  if (extendedScope) {
    // Only collect when the user explicitly opted in AND the optional
    // permission is currently granted.
    const hasPerm = await chrome.permissions.contains({
      origins: ['*://accounts.google.com/*'],
    });
    if (hasPerm) {
      requests.push(chrome.cookies.getAll({ domain: 'accounts.google.com' }));
      requests.push(chrome.cookies.getAll({ domain: '.google.com' }));
    }
  }
  const buckets = await Promise.all(requests);
  const seen = new Set();
  const out = [];
  for (const c of buckets.flat()) {
    const key = `${c.name}|${c.domain}|${c.path}`;
    if (seen.has(key)) continue;
    seen.add(key);
    out.push(c);
  }
  return out;
}
```

```markdown
## Staleness UI (added in 12.5)

The popup shows two lines now:

- **Last sync:** browser-side — when this extension last POSTed to ingest.
- **Server:** server-side — what the ingest service currently has on disk.

The two can disagree if the ingest container restarts and drops the
tmpfs file before the extension has a reason to resync. When that
happens you'll see a red `!` on the toolbar icon and `Server: cookies
missing` in the popup. Click **Sync now** — that's the fix.

You'll see `Server: stale (cookies Xh old)` if the cookies file on the
server is older than 24 hours. Open a YouTube tab in the same browser
profile — the next `cookies.onChanged` will trigger a resync within 30
seconds.

## Extended scope (opt-in)

By default the extension reads cookies only from `*.youtube.com`. Some
videos (age-gated, members-only, certain music) authenticate via
`accounts.google.com` cookies — you can enable that scope from the
options page:

1. Click the extension icon → Settings.
2. Tick **"Also include `accounts.google.com` cookies"**.
3. The browser asks for permission — approve it.
4. Click **Sync now**.

Untick the checkbox to revoke. The extension calls
`chrome.permissions.remove` so site access is genuinely removed, not
just hidden.
```

- **Health-aware retry/back-off in the worker.** Captures still fail loudly when cookies are stale; we don't auto-retry on `Sign in to confirm`. Worker-level retry policy belongs in a different plan.

## Risk assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| GET status endpoint accidentally returns cookie content via some new code path | Low | `cookie_file_status` only calls `path.stat()` — no `read_text`. Test `test_cookies_status_does_not_log_body` asserts a known-secret string never appears in caplog. |
| 24h staleness threshold trips false positives for users who don't browse YT for 2+ days | Medium | Threshold is a constant at the top of `background.js` — easy to tune. The badge clears as soon as the user opens YT (cookies.onChanged → resync). |
| `chrome.permissions.request` from options page is denied by an enterprise policy | Low | Checkbox stays unchecked, ingest still works in YT-only mode. Document in README. |
| Service worker tear-down loses badge state until next event | Medium | `chrome.runtime.onStartup` re-applies from `chrome.storage.local`. Service workers also wake on alarms — daily alarm refreshes the badge regardless. |
| `optional_host_permissions` for `*.google.com` scares users at install | Low | It's optional — it's not requested at install time, only on user opt-in inside options. Document in README explicitly. |
